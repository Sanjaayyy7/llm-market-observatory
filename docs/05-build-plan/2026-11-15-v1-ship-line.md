# LLM Market Observatory v1.0 Implementation Plan

**Plan v1.1** (C1 hardening, 2026-11-16): STATUS C1 checklist items 1–16 closed and DECISIONS rows 1–5 applied. Live checks are cited inline with their dates.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the v1.0 line (G0–G7 plus descriptive G8–G9): a governed SCD2 history of first-party LLM list prices rebuilt from LiteLLM git, the headline "Y% of top-tier models cut within 365 days", an Epoch ground-truth check, and a static dashboard on GitHub Pages.

**Architecture:** Python fetchers (`ingest/`) do all network I/O and write Parquet to `data/raw/`. dbt-duckdb builds staging → intermediate → marts with no network access. `analysis/` reads the marts and writes `exports/`. An Observable Framework site renders the exports. CI runs everything against small committed fixture Parquet.

**Tech Stack:** Python 3.12 + uv, DuckDB, dbt-core + dbt-duckdb, pandas, lifelines, statsmodels, pytest, ruff, Observable Framework (Node 24 LTS), GitHub Actions + Pages.

**Spec:** `docs/03-spec/design.md` v1.2 and `docs/03-spec/PRD.md` v1.2. Spike numbers: `docs/04-feasibility-spike/feasibility-spike.md`.

## Global Constraints

- Pins: Python 3.12; `duckdb>=1.5,<2`; `dbt-core~=1.12.6`; `dbt-duckdb~=1.11.1`; `pandas>=2.1,<3`; `uv.lock` committed. No dlt, Airflow, Dagster, Elementary or dbt-metricflow (G10 deferred).
  - `pandas<3` is there because lifelines 0.30.1 and 0.30.3 declare `pandas<3.0,>=2.1` (PyPI `requires_dist`, fetched 2026-11-16). Without the cap, the resolver falls back to lifelines 0.30.0 (2024-10-29), which was never declared compatible with pandas 3.
  - Dry-run resolve on 2026-11-16 (`uv pip compile --python-version 3.12`): `dbt-core==1.12.7`, `dbt-duckdb==1.11.1`, `duckdb==1.5.6`, `pandas==2.3.3`, `lifelines==0.30.3`, `statsmodels==0.15.0`.
  - `[tool.uv] python-preference = "only-managed"`. This host's `/usr/local/bin/python3.12` is an x86_64 binary that fails with "Bad CPU type in executable", and no arm64 3.12 is installed.
- Site: Observable Framework on Node 24 LTS (`.nvmrc` = `24`). Ship Parquet, never `.duckdb`. Pin the npm version exactly, to a release at least two weeks old: `@observablehq/framework` `1.13.4` (npm `latest`, published 2026-03-02, `engines.node >=18`).
  - Node 20 reached end-of-life on 2026-04-30.
  - Node 24 "Krypton" has been in maintenance LTS since 2026-10-20 and is supported until 2028-04-30.
  - Node 26 "Lithium" has been active LTS since 2026-10-28 (`nodejs/Release` `schedule.json`, fetched 2026-11-16). 26 was rejected because it was released (2026-05-05) after Framework 1.13.4.
- dbt never calls the network. Fetchers write raw Parquet under five fixed source directories, `data/raw/{litellm,arena,epoch,pypi,tokencanopy}/`:
  - `litellm`: partitioned `snapshot_date=YYYY-MM-DD/`.
  - The other four: partitioned `run_date=YYYY-MM-DD/`.
  - Each writes `part.parquet` inside its partition, appends one row to `data/raw/_freshness.parquet`, and is idempotent per partition (a re-run overwrites it).
- dbt always runs with `dbt/` as the working directory, so every relative path is relative to `dbt/`: `../data/warehouse.duckdb`, `../data/raw`, `../tests/fixtures/raw`. In the plan, that is written as the subshell `(cd dbt && uv run dbt …)`, so a persistent shell's working directory does not drift. Each `make` recipe line is already its own shell.
- CI has no network access to data sources and runs no LLM calls. It uses committed fixtures. There is one fixture layout:
  - `tests/fixtures/raw/<source>/` (and `tests/fixtures/raw/_freshness.parquet`): Parquet in the raw layout dbt reads.
    - Paths resolve through macro `raw_root()`, which returns `var('raw_root', '../tests/fixtures/raw' if target.name == 'ci' else '../data/raw')`.
    - A target in `profiles.yml` cannot carry vars.
  - `tests/fixtures/samples/<source>/`: upstream-format files (CSV, ZIP, Parquet slices) that parser unit tests read offline.
  - Golden fixtures: hand-worked inputs **and expected outputs**. The co-founder writes them before dispatch, independently of the code under test; builders never edit them.
    - The SCD2 golden lives in `dbt/tests/fixtures/`. dbt unit-test fixture files live in a `fixtures` subdirectory of a test path, and unit-test inputs must be the model's direct `ref`/`source` (docs.getdbt.com/docs/build/unit-tests, fetched 2026-11-16).
    - The KM golden lives in `tests/fixtures/golden/`.
- A committed `docs/prereg/*.md` is never edited. An amendment goes in a new dated file, and the result under the original prereg is still published. Task 8's `test_prereg_never_modified` enforces this.
- Price = first-party, standard tier, `blended = (3·in + 1·out)/4 × 1e6` USD per 1M tokens. Vertex, Bedrock, Azure and other clouds are not first-party.
- Cut = blended drop of ≥10% (`pct <= -0.10`) vs the previous version of the same canonical model. Correction = reverted within 14 days, or within 7 days of listing.
- Top-tier = Arena `text` / `overall` rank percentile ≤25%, with rank recomputed by rating within the snapshot, on the first snapshot within 60 days after listing.
- Canonical ID rule = design §6 (v1.2). Mode filter = design §5 (v1.2).
- Kill criteria = design §18. A tripped criterion stops the task. Report it; never work around it.
- **Owner gates (the only stops for the owner):**
  - S1: `gh repo create`, any push, enabling Pages, pushing a tag.
  - P3: any global install. Two are known: a Python 3.12 for G0, and for G7 the Node 24 default, gitleaks, and a Playwright browser if none is cached.
  - A1: the release drills, written by the owner without AI.
- **Co-founder decisions** (DECISIONS rows 3 and 5), each with an owner FYI:
  - G2 crosswalk approval, through the evidence test and a reviewer pass (Task 5).
  - Epoch benchmark scores unobtainable at G1.
  - G5 failing after one diagnosis pass.

  Each of these goes to a mini-council replan (3 Opus lenses).
- **Escalation order** (reconciles design §15 l.325 with the one-diagnosis rule):
  1. A kill criterion (design §18) applies its own action first.
  2. G5 gets exactly one diagnosis pass, then a mini-council replan. The Home page shows "validation pending" meanwhile. The Epoch check is never cut (PRD §11).
  3. Any other gate that fails twice goes to a mini-council replan (DECISIONS: escalation). The default cut is the next PRD §11 item; the only one left is cut 3, cron (Task 12). Crosswalk tests, the panel and the Epoch check are never cut.
  4. Changing a Global Constraint definition (cut, correction, top-tier) always goes to the co-founder plus a mini-council, never to a builder.
- Branch per gate: `gN-<slug>`. Fast-forward to `main` when the gate passes. `main` is always shippable. Commits use `<type>: <description>`.
- The co-founder owns three things:
  - `docs/drills/<slice>.md` for every merged gate: three questions, each followed by `Answer: _pending_`. The questions cover its grain, one test it relies on, and one failure mode.
  - `docs/DECISIONS.md` rows (`choice | rejected alternative | why | E-ID`). Builders never write them; they report each open choice as a `CHOICE:` line.
  - `docs/STATUS.md`.
- Every builder brief appends the upstream `FINDING:` lines its task consumes, plus a `DESCRIBE` of each raw or dbt relation it reads. Columns that only a probe can reveal (Epoch, PyPI) are named there, not guessed.
- The GateGuard hook asks for facts before the first Bash of a session. State them and retry. Its first-edit check is off for project files (DECISIONS row 2).

## Review Focus

1. **Null or changing `mode`.** Every key on 2023-09-06 has null mode. A key must not look delisted or relisted because its mode was filled in later. → Task 4 test `test_null_mode_key_not_delisted`.
2. **Zero or null prices.** Free previews and missing output costs: a move to or from 0 or null is never a cut, and those rows are excluded from cut detection. → Task 6 unit tests `zero_to_price_not_cut`, `price_to_zero_not_cut`.
3. **Float noise in per-token costs** (`1.5e-07` vs `1.4999999e-07`) must not create a price version. Compare per-1M prices rounded to 6 decimals. → Task 4 tests `test_float_noise_rounds_equal` (staging) and `test_equal_prices_no_new_version` (dimension).
4. **Arena renames and variants.** The 2026-10-20 display-name rename, "(High)" and "-thinking" all map to one canonical model, ranked at the best variant in the snapshot. Dated parentheticals such as "(03-25)" are separate API IDs and stay separate (design §6). → Task 5 tests `test_canon_collapses_variants`, `test_canon_keeps_dated_parens`, `test_rank_is_best_variant`.
5. **Interrupted or rewritten replay.** A crash mid-run, or a LiteLLM force-push that leaves the state sha out of history, must still produce the same hash as a clean full run. → Task 2 tests `test_partial_run_recovers`, `test_rewritten_history_full_replay`.
